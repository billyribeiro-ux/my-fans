# Evidence-based Svelte review — October 8, 2026

This review covers every Svelte component, every SvelteKit load function, request handling, and the frontend lifecycle helpers. The dependency cutoff remains October 7: Svelte 5.57.2, SvelteKit 3.0.1, TypeScript 6.0.3 and Node 24.21.0 LTS. The official Svelte MCP documentation and analyzer were used alongside the installed compiler, runtime code and browser tests. Analyzer results alone do not establish behavioral correctness.

## Deliberate choices

The project keeps the SvelteKit 3 Vite plugin configuration, `#lib` imports, `$app/state`, `refreshAll`, the new `goto` options, private environment modules and the fixed application origin. These match the [official version 3 migration guide](https://svelte.dev/docs/kit/migrating-to-sveltekit-3).

Successful authentication transitions use `goto(destination, { refreshAll: true })`. This performs the intended navigation and data refresh together, avoiding a window where an identity-keyed component is disposed by a separate refresh before it can navigate. See [navigation options](https://svelte.dev/docs/kit/$app-navigation#GotoOptions).

Component props remain reactive. No mutable user state is stored in a shared server module. Existing identity and resource keys remain where changing the key must dispose a security-sensitive workflow, request or draft. They are not used to force ordinary computed values to update. Shared context is unnecessary for the current explicit prop boundaries. See [state management](https://svelte.dev/docs/kit/state-management) and [key blocks](https://svelte.dev/docs/svelte/key).

The current official MCP documentation labels [component await expressions](https://svelte.dev/docs/svelte/await-expressions) and [remote functions](https://svelte.dev/docs/kit/remote-functions) experimental. This release keeps the stable server-load and explicit Rust API architecture. There is no measured requirement to enable those flags. `getAbortSignal()` requires an active derived or effect; event-driven mutations therefore retain explicitly owned `AbortController` lifetimes. See [getAbortSignal](https://svelte.dev/docs/svelte/svelte#getAbortSignal).

The Svelte skills supply review guidance, while the installed compiler and current official documentation resolve API details. One concrete example: the analyzer accepted a nested `$props.id()` call, but the compiler correctly required its declaration at the top level. Both checks are necessary.

The production frontend build retains Vite's advisory for the dynamically imported HLS player chunk: approximately 575 kB minified, 179 kB gzip. `PrivateVideo` loads that library only when adaptive playback needs it and native HLS is unavailable. This is a known on-demand video payload, separate from Svelte compiler diagnostics.
